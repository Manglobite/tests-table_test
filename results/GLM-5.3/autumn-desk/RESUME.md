# RESUME — проект «Осенний рабочий стол»

**Статус: задача выполнена.** Дата финализации: 2026-10-01.

Отдельный автономный веб-проект интерактивной 3D-сцены (Three.js r170 из
локальной копии `tree_js`, без внешних ресурсов) в `pets/island/autumn-desk/`.
Запуск: `make run` → http://localhost:8137/ (LAN: http://<host-ip>:8137/).

## Состав результата

- Резной дубовый стол, приоткрытое окно с осенним видом, солнцем, птицами и
  падающими листьями, анимированные шторы, ноутбук с Win11-подобным экраном
  блокировки (живые часы, демо-поле пароля только в памяти вкладки), открытый
  блокнот с рукописными страницами, настольный календарь с текущей датой,
  декор (чашка с паром, книги, лампа, сухие листья, картина).
- Интеракции: фокус камеры на 4 объектах (hit-testing по сцене), home по
  повторному клику/фону/Esc, плавный retarget без телепортаций; адаптация
  кадра под desktop и мобильный портрет (расширение FOV вместо дальнего
  отъезда); курсор pointer на десктопе.
- Сервер: `server.mjs` (только `public/`, защита traversal/скрытых/симлинков,
  GET/HEAD, no-store), `scripts/launch.mjs` (pid-файл, stop только своего
  процесса), Makefile (`run|stop|restart|status|check`), `.env.example`
  (HOST=0.0.0.0, PORT=8137).
- Проверки: `make check` = check-static (офлайн/приватность/целостность
  Three.js) + check-server (23 теста: жизненный цикл, HOST/PORT, traversal,
  MIME, симлинки, «stop не трогает чужих») + check-interactions (8 тестов:
  состояния фокуса, плавность, портретная адаптация, picking). Все зелёные.

## Проблемы, с которыми столкнулся

### 1. Фантомный экран ошибки WebGL (главный баг, найден пользователем)
`display: flex` в CSS для `.fatal` и `.laptop-overlay` перебивал атрибут
`hidden` (UA-стиль `[hidden]{display:none}` проигрывает селектору по классу).
Итог: полупрозрачный блок «В браузере недоступен WebGL» висел над рабочей
сценой на всех устройствах и перехватывал клики. Headless-проверка это не
ловила (анализировала пиксели канваса напрямую, минуя DOM-слои).
**Фикс:** `.fatal[hidden]`, `.laptop-overlay[hidden] { display: none; }`.

### 2. CLI сервера игнорировал `--env` (проверки висели)
В CLI-блоке `server.mjs` флаг `args.env` передавался в `resolveConfig`,
ожидающую `envFile` — некорректный `.env` молча игнорировался, сервер
поднимался на дефолтах и не завершался. **Фикс:** явный маппинг ключей.

### 3. Портретный кадр не влезал при жёстком клампе дистанции
Первая версия адаптации (чистый отъезд камеры с clamp 3.2×) на аспекте 0.45
обрезала объекты. **Фикс:** связка «умеренный отъезд (0.7–1.9× авторской
дистанции) + расширение вертикального FOV» — требуемая ширина влезает всегда,
без «телескопа» в туман.

### 4. Raycaster не обновляет матрицы
`three` r170 не вызывает `updateMatrixWorld` за raycaster — picking в
headless-тестах падал. **Фикс:** `camera.updateMatrixWorld()` +
`updateMatrixWorld(true)` для целей в `pickFocusId` (безопасно и в рантайме).

### 5. Приключения верификации в headless Chrome (инструменты, не проект)
- CDP `Input.dispatchMouseEvent` не доставлял события в headless-shell →
  перешёл на синтетические DOM PointerEvent/KeyboardEvent.
- `Page.captureScreenshot` и полноразмерный `toDataURL` WebGL-канваса
  «отравляли» следующий pixel-readback (зависание >45 c), конвейер кадров
  засыпал при простое → читал кадр через `drawImage` внутри rAF, PNG-снимки
  уменьшенные (480px), плюс тикер 1×1 canvas против засыпания.
- `pkill -f <pattern>` в отладочных командах убивал собственную сессию
  (паттерн совпадал с командной строкой) → трюк `[c]hrome`.
- Итоговая фазовая методика: свежий navigate на каждый чекпоинт,
  DOM-проверки первичны, пиксели — best-effort с ретраями.

### 6. Мелочи
- URL-конструктор нормализует `%2e%2e` и `\` — часть traversal-тестов
  проверяет «inside», а не «reject» (сырые socket-запросы покрывают обход).
- Keep-alive соединения fetch держали event loop теста → `closeAllConnections()`.
- DOM-warning «Password field is not in a form» → input обёрнут в форму.
- Кэш браузера показывал старую версию → `Cache-Control: no-store` + `?v=`
  в URL скрипта (и поддержка query-string в check-static).

## Что проверено

- `make check` — 36 автопроверок (статика 5 + сервер 23 + интеракции 8), зелёные.
- Headless Chrome (SwiftShader): сцена рендерится (яркое небо в окне,
  деревянные тона стола), клик по окну переводит в фокус «Окно», камера
  перелетает, сцена анимируется (motion 41k–144k), все модули грузятся,
  консоль чистая, сетевых запросов только локальные 200-е.
- Пользователем визуально: фантомная ошибка устранена после фикса CSS
  (сцена открылась на desktop и телефоне).

## Известные ограничения

- Полный визуальный проход интеракций (все 4 фокуса, ввод пароля, welcome,
  Esc/фон/retarget, мобильный портрет) выполнялся инструментально headless;
  финальный субъективный осмотр композиции остаётся за пользователем.
- Headless-верификация шла по кадрам канваса и DOM-состояниям: субпиксельная
  типографика (часы, дата календаря) проверена логикой отрисовки, не OCR.
- Сервер останавливается целью `make check` (финальная уборка теста) — после
  проверок нужен `make run`.

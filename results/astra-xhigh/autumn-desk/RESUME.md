## Что реализовано

### Пространственная сцена

Все основные предметы созданы средствами Three.js из геометрических примитивов и групп объектов:

- дубовый стол с процедурным рисунком древесины, декоративными фасадами, ручками, резными мотивами и точёными ножками;
- окно с рамами, прозрачными стёклами и одной створкой, повёрнутой в приоткрытое положение;
- осенние деревья за окном, дорожка и летящие птицы;
- шторы с анимируемой геометрией;
- листья на столе и падающие листья снаружи;
- ноутбук справа с клавиатурой, тачпадом и демонстрационным экраном блокировки;
- открытый блокнот с двумя страницами и содержимым спереди;
- настольный календарь слева;
- дополнительный декор: чашка, ручка, книги и ваза с сухими стеблями.

Освещение состоит из полусферического света, тёплого направленного солнца с тенями и дополнительного заполняющего источника. Использованы туман, тональная компрессия ACES и ограничение pixel ratio для уменьшения нагрузки.

Текстуры дерева, экрана ноутбука, блокнота и календаря рисуются через Canvas 2D при инициализации. Дата композиции фиксирована: 21 сентября 2026 года. Экран ноутбука содержит часы, дату, фон, профиль и изображение поля пароля. Поле не редактируется; сбор пользовательского ввода не реализован.

### Камера и взаимодействие

`public/js/focus.js` содержит независимую от рендера модель состояний: общий вид и четыре цели — окно, ноутбук, блокнот, календарь.

Положение камеры и точка взгляда постепенно приближаются к новой цели. Переключение цели не переписывает текущее положение камеры, поэтому retarget продолжается от текущего состояния без мгновенного скачка.

`public/js/picking.js` использует настоящий `THREE.Raycaster`. Луч строится из координат указателя, но выбор выполняется пересечением геометрии сцены, а не фиксированными экранными зонами. Идентификатор интерактивного объекта ищется вверх по цепочке родителей пересечённого меша.

Поддержаны:

- мышь и касания через Pointer Events;
- повторный выбор текущего объекта для возврата home;
- возврат по фону и Escape;
- отбрасывание жеста с заметным перемещением вместо клика;
- снятие обработчиков при завершении жизненного цикла.

Для портретного режима предусмотрены отдельный общий ракурс и увеличение дистанции при фокусировке. При изменении размеров пересчитываются размеры рендера, aspect ratio и целевая поза камеры.

### Жизненный цикл

`public/js/main.js` отвечает за создание WebGLRenderer, запуск анимации, адаптацию размеров, обработку потери и восстановления контекста, освобождение геометрии, материалов, текстур, теней и обработчиков событий.

При невозможности создать WebGLRenderer выводится понятное сообщение. Системная настройка `prefers-reduced-motion` отключает декоративную анимацию, сохраняя управление камерой.

### Сервер и локальная поставка

`server.py` использует только стандартную библиотеку Python. Публичный корень — строго `public/`.

Реализованы:

- чтение и проверка `HOST` и `PORT` из `.env`;
- настройки по умолчанию `HOST=0.0.0.0`, `PORT=8841`;
- команды `make run`, `make stop`, `make restart`;
- блокировка менеджера через `flock` для последовательного выполнения команд управления;
- подтверждение успешного запуска дочернего сервера через pipe;
- остановка через приватный Unix-сокет и случайный токен;
- отсутствие широкого завершения процессов по имени или порту;
- отказ при занятом порте и некорректной конфигурации;
- GET/HEAD для публичных файлов, без листинга каталогов и файловой записи;
- проверка URL, кодирования, скрытых компонентов, traversal и симлинков;
- открытие файлов с `O_NOFOLLOW` относительно файловых дескрипторов каталогов;
- разрешённые расширения файлов и корректные MIME-типы;
- CSP с запретом внешних ресурсов, сетевых соединений из клиентского кода и отправки форм;
- отключённое журналирование HTTP-запросов.

Служебное состояние хранится вне публичного каталога, в `.runtime/`.

## Возникшие сложности и принятые решения

### Локальная библиотека находится вне публичного корня

Требовалось одновременно использовать предоставленный файл Three.js, не менять исходную библиотеку и не раздавать файлы за пределами публичной директории.

Решение: в `public/tree_js/package/build/three.module.js` размещена побайтовая копия исходного файла с сохранённым лицензионным заголовком. Браузер импортирует её по локальному пути. Это не симлинк и не исключение из правил серверной раздачи. Автоматическая проверка сравнивает содержимое копии с оригиналом.

Таким образом, фактический браузерный импорт идёт из публичной копии, а не непосредственно из соседнего исходного каталога. Это решение явно описано в README.

### Нет браузера для проверки композиции

Нельзя было подтвердить реальный рендеринг, визуальное качество материалов, читаемость текстур, ошибки браузерной консоли и производительность на телефоне.

Решение: дополнительно написал тест построения настоящей сцены в Node.js с заглушкой Canvas 2D. Он проверяет конечность координат после анимации, положение центров ключевых объектов в кадре и наличие доступных лучей picking на desktop и двух портретных соотношениях сторон.

Такая проверка не рисует изображение и не заменяет браузер: она выявляет часть геометрических ошибок, но не доказывает качество композиции или удобство касаний. В README оставлен отдельный список ручной приёмки.

### Плавное перенаправление камеры

При прямой установке новой стартовой позиции переключение между объектами могло бы давать скачки.

Решение: состояние камеры хранится отдельно от выбранной цели. Выбор меняет только целевую позу; текущие координаты обновляются постепенно. Автотест проверяет, что сразу после выбора другой цели координаты не меняются, а последующий шаг движения ограничен.

### Безопасная остановка сервера

Остановка по порту или по сохранённому PID могла бы затронуть чужой процесс, особенно при устаревших служебных данных.

Решение: для штатной остановки не применяются сигналы по PID. Менеджер обращается к приватному Unix-сокету и предъявляет токен текущего экземпляра. Отдельные тесты проверяют занятый чужим сокетом порт и подложное состояние с PID постороннего процесса.

### Обход публичной директории через URL и файловую систему

Одной проверки строкового префикса пути недостаточно для кодированных обходов и симлинков.

Решение: URL декодируется с проверкой UTF-8, запрещаются опасные компоненты и остаточный процент после декодирования, контролируется принадлежность публичному корню. Компоненты файлового пути открываются с запретом следования симлинкам. Негативные тесты включают обычный traversal, двойное кодирование, скрытые файлы, неверные escape-последовательности и ссылки за пределы публичного корня.

### Ограниченный набор интеракций и поле пароля

Задание ограничивает базовые взаимодействия фокусом камеры и одновременно требует видимое поле пароля на ноутбуке.

Решение: поле является частью текстуры демонстрационного экрана, а не HTML-формой или настоящим вводом. Это сохраняет заданный объём интеракций и исключает сбор паролей. Решение описано в README; редактируемого поля в реализации нет.

### Ошибки во время реализации

На зафиксированных запусках автоматических проверок падений не было. Первый полный запуск прошёл с 7 JavaScript-тестами и 5 Python-тестами. После добавления геометрического теста сцены повторный запуск прошёл с 8 JavaScript-тестами и 5 Python-тестами.

Поэтому перечисленные выше сложности — ограничения и проектные вопросы, решённые при реализации, а не подтверждённые визуальные дефекты или ошибки, обнаруженные браузером.

## Выполненные проверки

Команда: `make test` из корня проекта.

### Статические проверки

- разбор синтаксиса Python через `ast.parse`;
- проверка синтаксиса JavaScript через `node --check`;
- разрешение локальных ES module import в публичной директории;
- поиск сетевых API, внешних HTTP-адресов и API постоянного хранения в прикладных JavaScript-модулях;
- побайтовое сравнение публичной копии Three.js с исходником.

Это целевые проверки исходников, а не полный формальный аудит безопасности. Отдельные сторонние линтеры и TypeScript в проект не добавлялись.

### JavaScript: 8 успешных тестов

1. Фокус окна и повторное нажатие для возврата home.
2. Фокус ноутбука и повторное нажатие для возврата home.
3. Фокус блокнота и повторное нажатие для возврата home.
4. Фокус календаря и повторное нажатие для возврата home.
5. Отсутствие мгновенного скачка при retarget и приближение к новой цели.
6. Изменение портретного кадрирования без мгновенного изменения текущей позиции.
7. Настоящий raycasting через обработчики указателя: вложенные объекты, фон, Escape, отбрасывание перетаскивания и cleanup.
8. Построение реальной сцены, конечность анимируемых координат, кадрирование центров и геометрическая доступность четырёх целей при 1440×900, 390×844 и 360×640.

### Python: 5 успешных тестов

1. Настройки по умолчанию и привязка к `0.0.0.0`.
2. Отказ при некорректных настройках и занятом порте без остановки чужого слушателя.
3. Запуск, повторный run, restart, stop и новый запуск с применением HOST/PORT.
4. Публичные файлы, MIME, HEAD, запрет POST, traversal, кодирования, скрытых файлов и симлинков.
5. Игнорирование подложного PID при stop без завершения постороннего процесса.

Тесты создавали временные копии внутри `autumn-desk/tests/`, запускали собственные серверы на свободных портах и удаляли их после завершения. Основной сервер не запускался автоматически из `make test`.

После проверок отдельно выполнены `make run` и HTTP-запрос через curl: получен статус 200.

## Итоговое состояние и ограничения

На момент завершения реализации основной сервер был запущен на `0.0.0.0:8841`; адрес для LAN-приёмки — `http://<host-ip>:8841`. Это зафиксированное состояние после запуска, а не гарантия его доступности в любой последующий момент.

Управление из корня `autumn-desk`:

```sh
make run
make stop
make restart
make check
make test
```

Инструкции и сценарий ручной проверки находятся в `README.md`.

Не проверены в реальном браузере: фактическое изображение WebGL, читаемость объектов и текстур, качество теней, удобство касаний, FPS, консоль и загрузка ресурсов, восстановление графического контекста и поведение на физических мобильных устройствах. Проверка этих пунктов оставлена пользователю в соответствии с исходными условиями.
